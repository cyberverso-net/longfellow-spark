# 0088 The proof inputs and the reuse of a proof

## Status

Accepted (2026-11-09, at the merge of pull request #145; proposed 2026-11-09 with #144). Amends [ADR 0062](0062-proof-on-demand.md): the text-only mode and its list of harmless files are replaced by the rule below. Amends [ADR 0087](0087-cross-check-with-upstream-at-every-gate.md) on one point: the cross-check runs at every gate, proof proved again or reused.

## Date

2026-11-09

## Context

Every gate proves the whole project from a clean session: `scripts/check.sh` runs `gnatprove --clean` before `gnatprove`, because a kept session returned stale results for unchanged checks (three false failures in stage 4), and [ADR 0020](0020-prover-configuration-step-budget.md) rejected session replay. The proof takes about 150 of the 163 minutes of `make check`; the other steps (build, partitions, tests, the command line with the cross-check of [ADR 0087](0087-cross-check-with-upstream-at-every-gate.md), vectors, lint) take about fifteen.

The proof reads a short list of files: the SPARK units under `src/`, the project file `longfellow_spark.gpr` (the source directories, the compiler switches through the project Alire generates under `config/`, the `Prove` package with the provers, the step budget, the timeout and the memory limit), the toolchain pinned by `alire.toml` (GNAT, GNATprove, sparklib, exact versions), and the gnatprove command lines of `scripts/check.sh`; the partition list `scripts/prove-partitions.txt` decides what a partition run proves. It does not read `tests/`, `cli/`, the rest of `scripts/`, the workflows, the vectors or the documents.

Of the four gates of 8 and 9 November 2026, three (#133, #141, #143) proved the same 37,810 checks on the same sources as the gate before them, about eight hours of the machine; a merge of `main` into the branch of #138, with the same sources, had no `prove` until the maintainer posted it by hand. [ADR 0062](0062-proof-on-demand.md) had given `scripts/remote-check.sh --text-only` an allowlist of files that cannot change the proof (Markdown, LICENSE, the configuration under `.github/`), extended by #132 to `scripts/measure/`; an allowlist of what is harmless grows one exception at a time, where the list of what the proof reads is short, stable, and can be read from the project file itself.

## Decision

**The proof inputs** of a commit are, each by its git object hash, one line each:

- `longfellow_spark.gpr`, and the tree of every directory its `Source_Dirs` names and the repository holds (`src/`); `config/` is generated by Alire from `alire.toml` and is recorded as "generated";
- `alire.toml` (the exact pins of the toolchain), and the lockfile whenever it is in the repository (`alire/alire.lock`, where Alire 2 keeps it, or `alire.lock`);
- `scripts/prove-partitions.txt`;
- every configuration pragma file (`.adc`) anywhere in the repository (none today);
- the gnatprove command lines of `scripts/check.sh` and the Makefile (the lines that name `gnatprove`, continuation lines joined first so that an option on a line of its own counts, comment lines excluded), as one hash.

The **digest** is the SHA-256 of that list. `scripts/remote-check.sh --digest [commit]` prints the list, the digest and the proved ancestor with the same digest, if any.

**The rule.** Before starting a run for a commit, `scripts/remote-check.sh` computes its digest and walks its ancestors, along every parent, within 200 commits, for one whose digest is equal and whose status `prove` is success. If it finds one, the machine runs `make check-reuse` (every check but the proof: build, partitions, tests, the command line with the cross-check, vectors, lint) and the status `prove` is posted as success with the description "proof inputs <digest> as <commit>, proved; build, test, cli, vectors, lint passed on prove-runner in N min". Otherwise the machine runs `make check` and proves from scratch, as before. A reused status counts as a proved ancestor for later commits: it names the commit it rests on, and every chain ends at a proof from scratch.

**The refusals.** The reuse is refused, and the proof runs, when the project file uses an attribute the list does not cover (`Source_Files`, `Excluded_Source_Files`, `Excluded_Source_Dirs`, `Source_List_File`, a configuration pragmas attribute), declares `Source_Dirs` more than once or inside a `case` statement, names a source directory by anything but a string literal without wildcards, names one the repository does not hold (`config/` excepted, generated by Alire), withs a project by path other than the generated one under `config/`, or when the repository holds a project file the list does not know (the known ones the proof does not read: `cli/longfellow_verify.gpr`, `tests/longfellow_spark_tests.gpr`). The list of inputs lives in one function of the script, `proof_inputs`.

**The machine always runs.** A reused proof saves the proof, not the gate: the fifteen minutes of checks run on every commit, so the harnesses, the command line, the cross-check with upstream, the vectors and the lint are exercised on the exact commit.

**The proof from scratch** stays the rule at three points, with `scripts/remote-check.sh --full`: every release tag, every milestone close, and once a week on `main`, started on Monday at 03:00 by a scheduled job on the maintainer's machine (`scripts/weekly-proof.plist`, a launchd agent running `--full origin/main`), detached on the machine as the tree runs of #84 are, its status posted on the head of `main`.

**`--text-only` goes.** Its cases, Markdown, LICENSE, `.github` configuration, `scripts/measure/`, are commits whose proof inputs are unchanged; they now take the fifteen minutes, which exercise what they may have changed.

## Alternatives considered

- **Extend the allowlist.** #132 did it once; every new kind of harmless file would need another record. The list of inputs needs none: a new source directory is read from the project file, a new configuration file is found in the tree, an unknown project file refuses the reuse.
- **Keep gnatprove's session between gates.** Rejected in stage 4 for stale results and in ADR 0020 for replay; "proved" means proved from scratch, and the project does not depend on the session's cache being right.
- **Prove the affected partitions only.** Would also save on changes of Ada, but needs the dependency closure of the units, generics and their instances included (the lesson of block 4a: a declaration in a generic's formal package enters every instance); a wrong closure would pass a proof that should have failed. Not taken; possible later, on top of this record.
- **No machine run when the inputs are unchanged.** The hosted `verify` workflow runs build, tests, command line, vectors and lint, but not the cross-check with upstream, and the machine's run is the record the status points to. Rejected: the fifteen minutes stay.
- **Compare diffs against the proved ancestor** instead of digests. The same rule with a weaker tool: a digest is a property of the commit alone, so a merge of `main` or a commit far from the proved one is handled without special cases.

## Consequences

- A change that does not touch the proof inputs costs about fifteen minutes of the machine instead of about 165, and the merge of `main` into a branch needs nothing by hand.
- The description of a reused `prove` names the proved commit and the digest; the gate's record is explicit about what was proved when.
- Every release, milestone close and week has a proof from scratch of `main`; the weekly job's schedule lives on the maintainer's machine, outside the repository, with its file in `scripts/`.
- The pull request of this record takes the full gate, under the rule in force when it was opened.
- A forgotten input is the risk. The source directories are read from the project file, the configuration files and the project files are found in the tree, and the unknown refuses; what the list cannot see is a change of the machine itself (the GNATprove installed there is the one `alire.toml` pins, fetched by Alire) or of Alire's own version, which the weekly proof from scratch bounds to a week.

## Verification impact

No Ada, no contract, no proof setting changes. The gate's rule changes: the proof runs again only when its inputs changed, by digest; `make check-reuse` is the gate's other mode, chosen by `scripts/remote-check.sh` and never by hand.
