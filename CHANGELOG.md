# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); the project does not yet follow semantic versioning in the strict sense, since its interface is the pinned specification rather than an API. Every entry names the decision records (`docs/adr/`) and the guide chapter (`docs/guide/`) that describe it; the trust model that says what is proved, tested and trusted is in the README.

## [Unreleased]

### Changed

- `Zk_Prover` and `Zk_Verifier` in two phases, as upstream's `commit`/`prove` and `recv_commitment`/`verify` (ADR 0085, #125): `Commit` takes the private inputs, builds the commitment and writes its root to the transcript the caller opened; `Prove_Committed` takes the public inputs, evaluates the circuit, checks the satisfiability and proves; `Receive` reads a proof at an offset of a buffer and writes its root; `Verify_Received` replays and verifies; `Sumcheck_Transcript.Replay_From_Statement` replays without the reset and the root. `Prove` and `Verify` keep their contracts as the composition of the phases on a fresh transcript; the two upstream example proofs are reproduced byte for byte as before. One change of order for the single proof: `Not_Satisfied` is found after the commitment, since the circuit can be evaluated only with the public inputs (ADR 0049 amended). For the mDoc layer, which commits two circuits before it proves either (#65).
- Every measurement series carries two labels, this project's commit or tag and the upstream commit measured in the same session (#127): the performance page states the convention and names d5e6be7, the pin, for every comparison it shows; `scripts/measure-mdoc.sh` prints both labels first; `scripts/measure/heap_v7.rs` prints the upstream commit it was built for. The pin does not move when a newer upstream is measured.
- The trusted base register notes upstream's commit 7ec62ec (24 October 2026), the fix of the carries in the multiply-accumulate of the delayed reduction of `fp_generic.rs`, and why the fault has no counterpart here: every product is reduced (ADR 0070) and the P-256 multiplication is proved against the integer model. No row changes; the pin stays at d5e6be7 (#123).

## [0.4.0] - 2026-11-07

Phase D, performance and memory: the production mDoc circuits of upstream at full scale, proved and verified with every contract proved. Milestone M2 closed the round trip at 8.13 s (ADR 0078); the memory milestone closes with the peak heap at 1.17 times upstream's for the prover and 1.30 times for the verifier on the hash circuit (ADR 0084), after a review of the whole repository (ADR 0083). The mDoc layer and the proof of age follow in 0.5.0 (ADR 0082).

- `Additive_Fft`, the Reed-Solomon extension on GF(2^128) by the additive FFT of Lin, Chung and Han, in the form of the production prover; the GF(2^128) prover encodes its rows with it and keeps no Lagrange table, P-256 kept the Lagrange encoder until `Rfft_P256` (chapter 8, ADR 0057). `gen_fft_vectors.py` and the harness `fft_kat`; the `config_invalid` case of `zk_prove.txt` moves to P-256, and a GF(2^128) case with more columns than the subfield holds is added.
- The mDoc production circuits of upstream, versions 7 and 6 with one attribute: archives, example proofs, witnesses and the extracted LFC2 circuits under `tests/vectors/upstream/mdoc/`, read by the independent `gen_mdoc_vectors.py` and loaded by `circuit_kat` (Phase D, ADR 0055 to 0059). `scripts/measure-mdoc.sh` measures the prover and the verifier on them, on macOS or Linux, with an optional profile per function.

### Changed

- The Lean correspondence marks its ECDSA row as no evidence for now: at 7bf8a6b upstream's `ecdsa_circuit_soundness` and `ecdsa_circuit_completeness` hold only vacuously on real keys, since the specification compares `[order]·PK` with the point at infinity by structural rather than projective equality (upstream's issue 224; pull requests 225 and 215 correct it, not yet merged). What covers the signature circuit is this project's Gold proof of the circuit's evaluation and the upstream proofs and vectors; what the circuit computes stays trusted (ADR 0011). The row is reread at their merge. No code change.
- The development process (`docs/process.md`) states how the tracking works on the points where it had drifted: a dependency between issues is a blocked-by relation, the label `blocked` is for a wait on something that is not an issue; an item is Ready only when every issue it is blocked by is closed; tasks of tooling and surveillance may have no milestone; Dependabot's pull requests carry `area: ci` and need no issue; the two cases that get the status `prove` without a proof run (a change without code through `--text-only`, a merge of `main` without code posted by the maintainer, named in the status). The Block form requires "Out of scope". `scripts/remote-check.sh --text-only` accepts the configuration files under `.github/` other than the workflows, beside Markdown and LICENSE. No code change.
- The toolchain is pinned in one place: `gnat_native 16.1.0` and `gprbuild 26.0.1` are dependencies in `alire.toml` beside `gnatprove 16.1.0`, and the workflow reads its versions from there. `actions/checkout` and `alire-project/setup-alire` are pinned to the commit of their release, the tag as a comment. The README gives the steps to reproduce the environment. No code change.
- `scripts/remote-check.sh --tree` runs detached on the proving machine, as the run on a pushed commit does: a lost ssh session, an expired token or a sleeping laptop no longer kills the run, and the machine powers itself off when done. `--tree-collect` picks up a tree run later. A tree run is refused while a run of either mode holds the machine; two launches at the same moment are not yet kept apart. The README describes it.
- The command-line build `proved` compiles `Pinned_Circuits` with its run-time checks, as every unit of `cli/src/` (ADR 0068 amended). The unit, outside the proof, was missing from the list of the project file. `scripts/check.sh cli` now reads the switches each unit was compiled with from its ALI file and fails if a unit of `cli/src/` lacks its checks or a unit of `src/` keeps them. The build passes `-s` to `gprbuild`, so that a change of switches recompiles the units it concerns: without it, an object directory from an earlier build kept `Pinned_Circuits` without its checks, and the new check caught it. The trust model says so.
- The assurance statements say what the proofs cover and no more. The circuit loader: its structure is proved, its decoding of the file is tested, its correspondence to Lean's circuit is checked by reading. The absence of run-time errors holds for the inputs that meet the preconditions, with a failed allocation, code outside SPARK and the termination of the samplers outside. Known-answer vectors are independent evidence, not a proof of the references. A circuit is executed safely and as its terms say, but what it computes is trusted. README, verification approach, trust model and Lean correspondence. No code change.
- The README no longer calls Longfellow ZK Google's: Google donated it in September 2026 to the Post-Quantum Cryptography Alliance, under Linux Foundation Europe, and upstream's repository is now longfellow-zk/longfellow-zk. The provenance lines of the vectors keep the name google/longfellow-zk, under which d5e6be7 was published. A new section, "About this project", states that the project is the author's personal project and that its views are the author's own, not those of the author's employer. No code change.
